1. DEPENDENCY AUDIT (no changes needed)

   Every third-party import in the code is listed in requirements.txt and
   installed in .venv (Python 3.12.5). The only import so far is httpx, in
   scripts/edgar_utils.py. Nothing was missing.

   The other listed packages (beautifulsoup4, lxml, pandas, yfinance,
   scikit-learn, matplotlib, pytest) are installed but no code uses them yet.

   Not added on purpose:

     instead of the decision tree.
   - Later-phase packages from docs/PLAN.txt and docs/ARCHITECTURE.txt
     (pydantic, sqlalchemy, fastapi, shap, xgboost, an LLM SDK).
     START_SMALL leaves these out for now.


2. PINNED VERSIONS

   requirements.txt
     Each package is pinned to the version installed in .venv:
       httpx==0.28.1          beautifulsoup4==4.15.0   lxml==6.1.3
       pandas==3.1.0          yfinance==1.7.0
       scikit-learn==1.9.1    matplotlib==3.11.2
       pytest==9.1.1
     Why: without versions, a fresh install could pull different versions
     than the ones the code was written against.

   requirements.lock (new file)
     Output of `pip freeze`: all 46 installed packages at exact versions,
     including the ones the packages above depend on.
       Install exactly:   .venv/bin/pip install -r requirements.lock
       Rebuild it:        .venv/bin/pip freeze > requirements.lock
     Rebuild it after adding or upgrading a package.


3. .env LOADING IN scripts/edgar_utils.py

   Before:
     - The code opened ".env" relative to the folder it was run from, as
       soon as the module was imported.
     - Running it from any other folder, or importing it with no .env (for
       example in tests), crashed with FileNotFoundError.
     - Values in .env overwrote variables already set in the shell.

   After:
     - .env is found from the file's own location (the project root), so the
       script works from any folder.
     - A missing .env no longer crashes the import.
     - Variables already set in the shell are kept (os.environ.setdefault).
     - Lines without "=" are skipped, and spaces around keys and values are
       trimmed.
     - get() raises a clear RuntimeError if SEC_USER_AGENT is not set,
       telling you to copy .env.example to .env.

   Checked: imported the module from /tmp and SEC_USER_AGENT loaded correctly.
   Not checked: no live request to the SEC API.
